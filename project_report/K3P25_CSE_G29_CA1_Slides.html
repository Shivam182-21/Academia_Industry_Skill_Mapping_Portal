Problem Context

The Academia–Industry Competency Divide

Systemic Challenges

Curriculum Revision Lag: Academic syllabi take 2–4 years to update, while enterprise software stacks change every few months.

Opaque Grading: CGPA and percentage scores fail to communicate practical code-level or architecture-level proficiency.

Algorithmic Design

Proposed NLP Pipeline vs. Naive Baseline

Baseline: Naive Keyword Matching

F1: 0.7059

Mechanism: Naive substring lookup (if skill in text.lower()).

Flaw 1 (False Positives): Substring collisions match unrelated words (e.g. 'C' in 'Cloud', 'CSS' in 'Access').

Flaw 2 (False Negatives): Misses all synonyms and abbreviations ('k8s' for Kubernetes, 'pgSQL' for PostgreSQL).

Proposed: Rule-Enhanced NLP Pipeline

F1: 0.9123

Boundary Regexes: Uses word-boundary patterns (\b(?:alias1|alias2)\b) eliminating 100% of substring collisions.

Taxonomy Normalization: Resolves diverse aliases to a single canonical technical competency slug.

Bloom Cognitive Scaling: Weights competencies by cognitive depth (Level 1-2: 1.0x, Level 3-4: 1.5x, Level 5-6: 2.0x).

Engineering Architecture

Four-Tier Decoupled System Architecture

Tier 1 · UI Layer

React 18 & Vite

TailwindCSS, Lucide icons, responsive role dashboards, interactive radial gauges, and instant one-click evaluator login.

Tier 2 · Gateway

FastAPI & JWT

Python 3.13 REST API with OAuth2 Bearer tokens, role-based access control (RBAC), and automated Swagger documentation.

Tier 3 · NLP Engine

Bloom Gap Engine

Boundary regex extractor, synonym mapper, Bloom cognitive depth scaling, and personalized remediation path generator.

Tier 4 · Data

SQLAlchemy 2.0

Relational database supporting SQLite for lightweight portability and PostgreSQL for enterprise campus deployments.
